Bab 1Gambaran Sistem

CBT berjalan sebagai tiga kontainer Docker di satu server. Siswa dan staf mengaksesnya lewat browser di jaringan sekolah.

KontainerIsiCatatan
cbt-frontendTampilan web (Nginx)Satu-satunya yang membuka port ke jaringan, bawaan port 80. Meneruskan /api ke backend.
cbt-backendServer aplikasi (Go)Port 8080 di jaringan internal Docker. Health check di /health.
cbt-postgresBasis data PostgreSQL 16Data disimpan di volume cbt_postgres_data.

Kebutuhan

  • Docker: Docker Desktop (Windows) atau Docker Engine dengan Compose (Linux), dalam keadaan berjalan.
  • Jaringan lokal: server dan perangkat siswa berada di jaringan yang sama. Beri server alamat IP tetap agar alamat ujian tidak berubah.
  • Akses internet untuk perangkat siswa dan staf: tampilan memuat huruf dari Google Fonts dan gaya rumus (KaTeX) dari cdn.jsdelivr.net. Tanpa internet, aplikasi tetap berjalan dengan huruf cadangan, tetapi tampilan rumus matematika bisa berantakan.

Waktu server

Batas waktu ujian dihitung dari jam server, bukan jam perangkat siswa. Pastikan jam server tepat dan zona waktunya Asia/Jakarta (variabel TZ).

Bab 2Instalasi Pertama

Langkah 1. Siapkan berkas .env

Salin .env.example menjadi .env di folder yang sama dengan docker-compose.yml, lalu isi:

VariabelIsi
JWT_SECRETWajib. Nilai acak minimal 32 karakter. Buat dengan openssl rand -hex 32. Backend menolak berjalan bila kosong, kurang dari 32 karakter, atau sama dengan nilai contoh lama.
DB_PASSWORDWajib diganti dari nilai contoh. Password basis data.
DB_USER, DB_NAMEBawaan cbt_user dan cbt_db.
APP_PORTPort web, bawaan 80.
TZAsia/Jakarta.
PentingSetelah basis data pertama kali dibuat, jangan mengganti DB_PASSWORD di .env tanpa mengganti password di PostgreSQL juga. Backend tidak akan bisa terhubung.

Langkah 2a. Komputer Windows (dibangun dari kode sumber)

  1. Buka Docker Desktop dan tunggu sampai berstatus berjalan.
  2. Klik ganda docker-start.bat, atau jalankan .\docker-start.ps1 di PowerShell dari folder proyek.
  3. Setelah muncul [SUKSES] Sistem CBT berhasil dijalankan, buka http://localhost di server, atau http://<IP-server> dari perangkat lain.

Untuk menghentikan: klik ganda docker-stop.bat.

Langkah 2b. Server Linux (image siap pakai)

cd /opt/cbt/deploy
bash setup.sh        # membuat .env dari contoh bila belum ada, lalu berhenti
nano .env            # isi JWT_SECRET dan DB_PASSWORD
bash setup.sh        # menarik image dan menjalankan sistem

Skrip menampilkan status kontainer dan alamat akses di akhir.

Bab 3Setelah Instalasi

Akun bawaan

Saat basis data masih kosong, sistem otomatis membuat data contoh beserta akun berikut:

PeranUsernamePassword
Admin kurikulumadminadmin123
Guru / pengawasguru1guru123
Siswa contohsiswa1 – siswa3siswa123
PentingPassword ini tercantum di dokumentasi publik proyek. Segera ganti password admin lewat menu Guru dan Staf, lalu hapus akun dan data contoh sebelum dipakai ujian sungguhan.

Membersihkan data contoh

Skrip deploy/cleanup-dummy-data.sql menghapus data percobaan dari semua master data, kecuali akun admin. Periksa dan sesuaikan daftar username di dalamnya, buat cadangan (Bab 5), lalu jalankan:

docker exec -i cbt-postgres psql -U cbt_user -d cbt_db < cleanup-dummy-data.sql
PerhatianPenghapusan bersifat permanen.

Pentingdocker compose down aman karena volume data tidak ikut terhapus. Jangan menambahkan opsi -v: opsi itu menghapus volume basis data.

Bab 5Cadangan dan Pemulihan Data

Kapan dipakai: sebelum dan sesudah pekan ujian, sebelum pembaruan besar, dan sebelum menjalankan skrip pembersihan.

Mencadangkan basis data

docker exec cbt-postgres pg_dump -U cbt_user -Fc -f /tmp/cbt.dump cbt_db
docker cp cbt-postgres:/tmp/cbt.dump ./cbt-2026-09-27.dump

Ganti tanggal pada nama berkas. Simpan salinannya di luar server, misalnya di diska eksternal.

Memulihkan basis data

docker cp ./cbt-2026-09-27.dump cbt-postgres:/tmp/cbt.dump
docker exec cbt-postgres pg_restore -U cbt_user -d cbt_db --clean --if-exists /tmp/cbt.dump
docker compose restart backend
PentingPemulihan menimpa seluruh data saat ini. Jangan lakukan saat ujian berlangsung.

Berkas unggahan (gambar soal)

Pada instalasi deploy/, gambar yang diunggah guru tersimpan di volume cbt_uploads_data. Cadangkan dengan:

docker run --rm -v cbt_uploads_data:/data -v "$PWD":/backup alpine tar czf /backup/uploads-2026-09-27.tgz -C /data .
Perhatiandocker-compose.yml di folder utama proyek (dipakai docker-start.bat) belum memiliki volume untuk folder unggahan. Pada instalasi itu, gambar soal tersimpan di dalam kontainer dan dapat hilang saat kontainer dibangun ulang.

Bab 6Pembaruan Aplikasi

Instalasi deploy/ mendukung pembaruan otomatis lewat deploy/auto-update.sh. Skrip ini:

  • memeriksa image baru di Docker Hub,
  • hanya memasang image yang lolos verifikasi tanda tangan cosign dari alur rilis resmi,
  • menunda pembaruan selama ada jadwal ujian aktif atau sesi siswa yang belum selesai.

Memasang jadwal pembaruan

chmod +x /opt/cbt/deploy/auto-update.sh
sudo crontab -e
# tambahkan baris berikut (cek setiap 10 menit):
*/10 * * * * /opt/cbt/deploy/auto-update.sh >> /var/log/cbt-auto-update.log 2>&1

Server membutuhkan program cosign dan akses HTTPS keluar ke registry-1.docker.io, auth.docker.io, tuf-repo-cdn.sigstore.dev, dan rekor.sigstore.dev. Langkah pemasangan cosign ada di docs/PANDUAN_OPERASIONAL.md bagian 6.

KeperluanPerintah
Melihat riwayat pembaruantail -f /var/log/cbt-auto-update.log
Menjeda pembaruantouch /opt/cbt/deploy/.update-paused
Mengaktifkan lagirm /opt/cbt/deploy/.update-paused
Memperbarui sekarangFORCE=1 /opt/cbt/deploy/auto-update.sh (hanya di luar jam ujian)
InfoUntuk kembali ke versi tertentu: ubah image: di deploy/docker-compose.yml ke tag versinya, buat berkas .update-paused, lalu jalankan docker compose up -d.

Bab 7Mengatasi Masalah

GejalaPenyebab dan penanganan
Backend berhenti dengan pesan "JWT_SECRET minimal 32 karakter"Isi JWT_SECRET di .env dengan hasil openssl rand -hex 32, lalu jalankan ulang.
docker-start.bat: "Gagal menjalankan Docker Compose"Docker Desktop belum berjalan. Buka Docker Desktop, tunggu sampai aktif, lalu ulangi.
Halaman tidak bisa dibuka dari perangkat lainPeriksa IP server, firewall untuk port APP_PORT, dan pastikan perangkat berada di jaringan yang sama.
Port 80 sudah dipakaiHentikan layanan lain di port 80, atau ubah APP_PORT lalu akses dengan http://<IP>:<port>.
Log backend: "Falling back to SQLite"Backend gagal terhubung ke PostgreSQL dan beralih ke berkas SQLite lokal. Data yang masuk tidak tersimpan di basis data utama. Periksa kontainer cbt-postgres dan isian DB_*, lalu mulai ulang backend.
Rumus matematika tampil berantakanPerangkat tidak dapat mengakses cdn.jsdelivr.net. Pastikan jaringan sekolah mengizinkan akses ke alamat itu.
Jadwal tidak muncul bagi siswaPeriksa jam server dan zona waktu, lalu minta admin memeriksa status event, jadwal, dan kunci bank soal.
